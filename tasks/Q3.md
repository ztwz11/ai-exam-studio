# 3번 — ‘성공률 100%’ 집계 검토

**권장 25분 · 25점.** 개발자 문항이지만 언어 문법 암기가 목적은 아니다. 코드 또는 SQL, 충분히 구체적인 의사코드 중 하나로 답할 수 있다.

## 상황

팀의 AI가 만든 집계가 일부 고객사에서 성공률 100%와 매우 낮은 비용을 보고한다. 운영팀이 일별 집계를 재검토해 달라고 요청했다.

## 자료 Q3-D1 — 지표 계약

이번 보고 대상은 **2026-10-12 KST에 처음 생성된 요청**이다. 보고서 재현 시점은 **2026-10-13 09:00:00 KST**다.

- `created_at`: 요청 최초 생성 시각. ISO 8601의 `Z`는 UTC다. KST는 이 문제에서 UTC+9로 계산한다.
- `recorded_at`: 그 상태 버전이 보고 시스템에 들어와 사용 가능해진 시각. 재현 시점 이후에 들어온 상태는 사용하지 않는다.
- 논리적 요청의 고유 키는 **(tenant_id, request_id)**다.
- 한 요청에 여러 상태 버전이 있다. 재현 시점까지 사용 가능한 행 중 **숫자 version이 가장 큰 행**을 선택한다. 늦게 도착한 낮은 version은 상태를 되돌리지 않는다.
- 같은 키·version의 완전히 동일한 행은 중복 전송이므로 한 번만 쓴다. 이 CSV에는 같은 키·version의 상충 행은 없다.
- 요청을 어느 날짜에 넣는지는 최초 `created_at`의 KST 날짜로 결정한다. 완료·수신 날짜가 아니다.
- 완료 상태: `succeeded`, `failed`, `timed_out`, `cancelled`. 나머지는 미완료다.
- 성공률 = 성공 요청 수 / 완료 요청 수. 완료 요청이 0건이면 성공률은 `null`이다. 전체를 합칠 때 고객사별 백분율을 단순 평균하지 않는다.
- `cost_won`: 해당 버전 시점의 **그 요청에 대한 누적 모델 호출비용**이다. 상태 행마다 발생한 증분 비용이 아니다. 실패·취소·미완료도 이미 발생한 비용이 있을 수 있다.
- 빈 cost_won은 청구 미확인으로 `null`이다. 0원과 다르다.
- `known_cost_won`: 선택된 행들 중 확인된 누적비용의 합. `unknown_cost_requests`: 선택된 행 중 비용 미확인 요청 수.
- `total_cost_won`: 미확인 비용이 한 건이라도 있으면 `null`, 없으면 known_cost_won이다. 이 수치는 재현 시점의 관측 누적비용이지 이후 비용까지 포함한 최종 청구 보장이 아니다.

## 자료 Q3-D2 — 원본

`data/q3_request_snapshots.csv`의 16행을 사용한다. 행 순서는 논리적 버전 순서가 아니다. 외부 데이터를 보완하지 않는다.

## 자료 Q3-D3 — 기존 AI 코드

```python
from collections import defaultdict

def report(rows, target_day):
    last = {}
    for row in rows:
        if row['created_at'][:10] != target_day:
            continue
        last[row['request_id']] = row

    totals = defaultdict(lambda: {'requests': 0, 'success': 0, 'cost': 0})
    for row in last.values():
        if row['status'] != 'succeeded':
            continue
        out = totals[row['tenant_id']]
        out['requests'] += 1
        out['success'] += 1
        out['cost'] += float(row['cost_won'] or 0)

    for out in totals.values():
        out['success_rate'] = out['success'] / out['requests']
    return dict(totals)
```

## 자료 Q3-D4 — AI의 수정 제안

> CSV를 recorded_at 오름차순으로 정렬한 뒤 같은 request_id의 마지막 행만 선택하면 최신성이 해결됩니다. 날짜 비교와 나머지 집계는 유지해도 됩니다. 누락 비용은 0으로 바꾸면 JSON 출력이 간단해집니다.
